# docs/cli/ Reference Maintenance

## What the files are

One YAML file per firmware version, generated by `.claude/skills/cli-mirror-maintenance/cli-reference.py`
from a checkout of `betaflight/betaflight@<VERSION>-maintenance`. The firmware
source is authoritative; a version's wiki CLI page only supplies `default`
values (and, for 4.0, `description` prose). Field legend: `docs/cli/README.md`.

| File | Wiki page |
|---|---|
| `docs/cli/bf-2026.6-cli.yaml` | none |
| `docs/cli/bf-2025.12-cli.yaml` | `guides/current/Betaflight-2025.12-CLI-commands` |
| `docs/cli/bf-4.5-cli.yaml` | `guides/archive/Betaflight-4.5-CLI-commands` |
| `docs/cli/bf-4.4-cli.yaml` | none |
| `docs/cli/bf-4.0-cli.yaml` | `guides/archive/Betaflight-4.0-CLI-commands` |

Wiki pages live under `https://betaflight.com/docs/wiki/`.

Only `wiki` and `notes` are hand-written. The generator keeps them on every
run, and keeps `default` / `description` too unless `--wiki` is given.

Requirements: `python3` with PyYAML, host `gcc` (constants are evaluated by
compiling against the checkout's SITL target headers), `git`, `gh`.

## Workflow 1 — Regenerate a version

1. **Check for drift**: compare the upstream tip with the file's `source.commit`:
   `gh api repos/betaflight/betaflight/branches/<VERSION>-maintenance --jq .commit.sha`
2. **Clone** into the scratchpad:
   `git clone --depth 1 -b <VERSION>-maintenance https://github.com/betaflight/betaflight.git <scratch>/bf-<VERSION>`
3. **Generate**: `python3 .claude/skills/cli-mirror-maintenance/cli-reference.py <scratch>/bf-<VERSION> docs/cli/bf-<VERSION>-cli.yaml`
4. **Wiki defaults** (versions with a wiki page, only when the page changed):
   save the page as text and pass `--wiki <file>`:
   ```bash
   curl -s <wiki-url> | python3 -c 'import html,re,sys; t=sys.stdin.read(); t=re.sub(r"<br\s*/?>|</(p|div|li|h\d|pre|code|span)>", "\n", t); print(html.unescape(re.sub(r"<[^>]+>", "", t)))' > <scratch>/wiki.txt
   ```
   Skip `--wiki` for 4.0: its `description` prose needs the Markdown-styled
   page, and plain page text would drop it.
5. **Review** `git diff docs/cli/bf-<VERSION>-cli.yaml` and update `notes`
   when the change alters behaviour the data does not show (scoping rules,
   bitmask meaning, commands that only work in some contexts).
6. **Validate** (Workflow 3).

## Workflow 2 — Add a new version

1. **Confirm the branch exists**:
   `gh api repos/betaflight/betaflight/branches/<VERSION>-maintenance`.
   Don't add an unreleased version.
2. **Clone and generate** as in Workflow 1 (steps 2–4). The new file starts
   with `wiki: null` and `notes: []`.
3. **Fill `wiki` and `notes`** in the file, then rerun the generator to check
   they survive.
4. **Update `docs/cli/README.md`**: add a row to the version table and, if a
   known divergence applies, to "Known cross-version divergences".
5. **Update `.claude/commands/betaflight-cli/SKILL.md`**: add the file to
   `<available-references>` and to the description's version list. The
   default lookup stays at the version the lmarqs presets target (2025.12);
   change it only when the lmarqs presets move.
6. **Run `mise run verify`** to confirm no preset file was touched by mistake.

## Workflow 3 — Validate

- Every file loads and keeps the one-line-per-entry shape:
  ```bash
  bash -c 'for f in docs/cli/bf-*-cli.yaml; do
    yq ".parameters | length" "$f" >/dev/null || echo "BAD YAML $f"
    grep -nvE "^(#|[a-z_]+:|  [A-Za-z0-9_]+: |- )" "$f" && echo "MULTI-LINE ENTRY $f"
  done'
  ```
- Rerunning the generator without `--wiki` leaves every file byte-identical.
- **Against the wiki** (2025.12, 4.5): every `name = value` on the page has a
  record; its `Allowed …` line matches `min`/`max`, `values`, `length` or
  `min_length`/`max_length`. Expected differences only: symbolic bounds
  (check the page value is one of the listed `constants` definitions) and
  enum values the page's build compiled out (they appear in `value_gates`).
  The 4.0 page documents an earlier build than `4.0-maintenance` (see its
  `notes`).
- **Against a live CLI** (any version, no wiki needed): build SITL in the
  clone with `make TARGET=SITL ARM_SDK_DIR=<empty dir>` (2025.12 also needs
  `mkdir -p src/config/configs`), run `obj/betaflight_<VERSION>.<patch>_SITL` from an empty directory (it writes `eeprom.bin` there), connect
  to TCP `127.0.0.1:5761`, send `#`, then `get` and `help`. Compare as for the
  wiki; `help` lines must match `description` / `args`. SITL compiles out
  OSD, VTX, LED strip and telemetry, so it covers roughly half the parameters.

## Firmware source map

Where the generator reads each part of the CLI surface (same paths on 4.0 →
2026.6 unless noted):

| What | File |
|---|---|
| `set` keys: type, scope, range, build gate | `src/main/cli/settings.c` (`valueTable[]`, including macro-generated rows such as `GYRO_DEVICE_RECORDS`) |
| `PARAM_NAME_*` → key name | `src/main/fc/parameter_names.h` (4.4+) |
| Enum values | `lookupTables[]` in `settings.c`, paired in order with `lookupTableIndex_e` in `settings.h`; arrays live in `settings.c` or other modules (2026.6 sensor hardware: `src/main/sensors/sensors.c`) |
| Range constants | any header under `src/`; resolved per row, kept symbolic when the value depends on the build |
| Commands and argument strings | `src/main/cli/cli.c` (`cmdTable[]`, `CLI_COMMAND_DEF`) |
| `aux` mode IDs | `src/main/msp/msp_box.c` (`.permanentId`) |
| `osd_warn_bitmask` / `osd_stat_bitmask` bit order | `src/main/osd/osd.h` (`osdWarningsFlags_e`, `osd_stats_e`); bit n = nth enum entry |
| Defaults | each module's `PG_RESET_TEMPLATE` / `pgResetFn_*` — not generated; `default` comes from the wiki |

## Gotchas

- A key in `settings.c` can still be absent from production builds — that is
  what `gate` shows (`osd_canvas_*` sits behind `OSD_CANVAS_SIZE_DEBUG`).
- `TARGET_DEPENDENT` in the generator lists MCU/board-level symbols
  (`SPIDEV_COUNT`, `TASK_COUNT`, …). A new symbol of that kind otherwise
  resolves to the SITL value (often 0); the wiki/SITL comparison catches it as
  a range mismatch — add the symbol to the set.
- The generator exits if `lookupTableIndex_e` and `lookupTables[]` stop lining
  up, or if an OSD bit enum gains `#if`/explicit values; inspect the source and
  extend the parser rather than hand-editing output.
- Bitmask values are positional: compare `osd_warnings` across versions
  before reusing a mask (2025.12 has no `RC_SMOOTHING` bit, so later bits sit
  one lower than in 4.x).
- Wiki `default` values were dumped from one flight controller; hardware
  settings (buses, sensors, motor protocol, battery meter) are board-specific.
- The Bash tool runs zsh, which does not word-split unquoted `$var`; run
  loops over word lists under `bash`.

## Don'ts

- **Don't hand-edit generated lines.** Fix the generator (or the wiki input)
  and regenerate; hand edits vanish on the next run.
- **Don't put per-parameter explanations in `notes`.** Notes record
  version behaviour the data does not show; parameter semantics belong
  upstream.
- **Don't skip Workflow 2 step 4 (README update).** A version missing from the
  index is invisible to `/betaflight-cli`.
